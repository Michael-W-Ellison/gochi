Software Design Document (SDD)
Advanced Tamagotchi Digital Pet System
Version: 1.5
Date: October 2026
Author: System Architecture Team

1. Introduction
1.1 Purpose
This document describes the software architecture and design for an advanced Tamagotchi-style digital pet system that simulates complex biological and behavioral processes in a virtual creature requiring continuous care and interaction.
1.2 Scope
The system encompasses a sophisticated digital organism with multi-layered needs, evolutionary capabilities, social interaction systems, and adaptive AI behaviors that respond dynamically to user care patterns and environmental conditions.
1.3 System Overview
Unlike traditional Tamagotchi devices, this advanced system implements:

Realistic biological simulation with multiple interconnected physiological systems
Adaptive personality development based on care history
Social play with other digital pets (without personal information or messaging)
Evolutionary mechanics allowing trait inheritance
Machine learning-driven behavioral adaptation
Cross-platform synchronization and cloud persistence

Version 1.1 adds the player-facing game systems built on these foundations: care rewards and a
shop (3.7), activities (3.8), requests, reactions and preferences (3.9), session and lifecycle
management including optional hibernation (3.10), save slots and backups (4.1), a REST API (4.3),
the environment, AR and adaptation features (5.1 - 5.3), including AR playdates through the cloud
hub (4.2, 5.2).

3.1.2 BiologicalSystems Class
cppclass BiologicalSystems {
    struct VitalStats {
        float health;           // 0.0 - 1.0
        float energy;          // 0.0 - 1.0
        float hydration;       // 0.0 - 1.0
        float nutrition;       // 0.0 - 1.0
        float happiness;       // 0.0 - 1.0
        float stress;          // 0.0 - 1.0
        float fatigue;         // 0.0 - 1.0
    };
    
    struct PhysiologicalProcesses {
        float metabolicRate;
        float digestiveEfficiency;
        float immuneStrength;
        float cognitiveCapacity;
        float emotionalResilience;
    };
    
    struct Physiology {                 // Organ systems, 0.0 failing - 1.0 healthy
        float stomach;                  // Food not yet digested (above 1.0 overfull)
        float bowel, bladder;           // Waste waiting to be passed
        float digestiveHealth;          // Scales digestion speed and absorption
        float cardiovascularHealth;     // Fitness; raised by exercise, fades without it
        float respiratoryHealth;        // Harmed by foul air, recovers in fresh air
        float nervousHealth;            // Worn by long-term stress, restored by calm
    };
    
    void processMetabolism(float deltaTime);
    bool eat(float amount);             // True if overfull: the pet throws up
    void drink(float amount);           // Fills the bladder
    void exercise(float amount);        // One play session = 1.0
    void processDigestion(FoodItem food);
    void processExercise(ExerciseType type, float duration);
    void processRest(float deltaTime, float sleepQuality);
    float calculateLifespan();
    void checkDeathConditions();
};

Rest: while the pet sleeps, fatigue falls by 0.5 x quality and energy rises by 0.15 x quality
per game day. Sleep quality comes from the pet's surroundings (section 5.1) and is multiplied
by 1.25 with a bed. A pet falls asleep when very tired and wakes only once fatigue is at or below
0.2 and energy at or above 0.5, so it does not wake and fall asleep repeatedly.

Decay multipliers: the rates at which hunger, thirst, fatigue and energy drain change are
multiplied by the pet's items (section 3.7) and its environment (section 5.1).

Physiology: the stomach digests 0.6 per game day (scaled by digestive health), and half of what
is digested becomes waste in the bowel; drinking fills the bladder. Eating past the stomach's
capacity (for example many treats at once) makes the pet throw up, losing nutrition and harming
digestion, and a meal's nutrition is scaled by 0.5 + 0.5 x digestive health. Fitness falls 0.02
per game day without exercise (to 0.3) and rises with play, exploring and walks. Foul air (from a
dirty living area, section 3.11) lowers respiratory health; fresh air restores it. Stress above
0.6 wears the nervous system, and a worn one makes stress build faster. An unfit heart or weak
lungs make energy drain faster, and any organ system below 0.5 costs health.

Kidneys, eyes, teeth and hearing (per game day): the kidneys' reserve falls by 0.00012 x senescence
x kidney aging (1.0 for cats, 0.6 for dogs), plus 0.00005 for an adult with inherited kidney
disease, scaled by care (a kidney-support diet halves it); kidney health is capped at the reserve,
falls with hydration below 0.25 and recovers 0.01 when hydration is above 0.5. Below 0.7 it speeds
thirst by 1 + (0.7 - kidney health). Eye health falls with foul air (air quality below 0.5) and by
0.004 x the breed's eye predisposition (eye wipes halve it), and heals 0.01 x (1 - 0.8 x
predisposition). Dental health falls 0.0015 x dental predisposition (1, or 1.5 for crowded teeth);
brushing removes 0.1 of plaque and halves it for the day. Hearing is set at birth (section 3.12)
and falls 0.0001 x senescence. Eyes or teeth below 0.5 add stress; kidneys and teeth below 0.5
cost health like the organ systems. Inherited heart disease makes the heart's aging 20% faster.

Death: a pet dies when health or hydration reaches 0.0, or nutrition and energy both do. The
cause of death is recorded and shown to the player (for an untreated illness, its name). See
section 3.10 for hibernation.

Environmental input: before each update the pet passes its body an EnvironmentData from its own
environment (section 5.1): the hour, daylight (1.0 by day, dimmed to 0.4 - 0.7 by cloud, rain,
storms, snow and fog, 0.0 at night) and air quality (from the living area, section 3.11). Other
sources may call processEnvironmentalInput directly.

Hormones (0.0 - 1.0; each moves towards a target at its own rate per game day, and events add
pulses):
  Cortisol   target 0.1 + 0.8 x stress - 0.3 x oxytocin (rate 4). Pulses: hardships (injury,
             illness, accidents, throwing up) 0.5 x intensity, scolding 0.2, medical care 0.05,
             unwanted affection 0.1. Above 0.3 it suppresses immunity (up to 40%), raises the
             metabolic rate (x (1 + 0.3 x cortisol)) and lowers sleep quality (x (1 - 0.3 x cortisol)).
  Growth     target 0.8 young, 0.3 adult, 0.3 - 0.15 x senescence senior; doubled + 0.2 in deep
             sleep (rate 6). Organ recovery is scaled by 0.5 + growth, health recovery adds
             0.01 x growth per game day, and exercise builds fitness x (0.7 + 0.6 x growth).
  Serotonin  target 0.15 + 0.25 x exercise need met + 0.25 x company met + 0.2 x daylight +
             0.15 x nutrition - 0.2 x cortisol (rate 2); pulses from meals and exercise. Happiness
             drifts by 0.005 per game day towards 0.3 + 0.4 x serotonin.
  Oxytocin   target 0.1 + 0.2 x company met (rate 3); pulses from petting 0.25, grooming 0.15 and
             treats 0.1, times the reaction multiplier. Lowers cortisol; stress falls faster
             (0.02 + 0.03 x oxytocin per game day) when wellbeing is good.
  Melatonin  target 0.9 x (1 - daylight), at least 0.5 asleep (rate 8). Awake fatigue builds
             x (1 + melatonin); sleep quality x (1 + 0.2 x melatonin); metabolism x (1 - 0.1 x melatonin).

Derived processes, recomputed each update: metabolicRate = (1.2 young, else 1.0) x (1 - 0.25 x
senescence) x the hormone factors above, and scales nutrition decay; cognitiveCapacity = (0.9 young,
else 0.8) x (1 - 0.3 x senescence) x (1 - 0.3 x sleep debt level), and scales trick training by
cognitiveCapacity / 0.8; emotionalResilience = 0.25 + 0.3 x serotonin + 0.2 x oxytocin + 0.25 x
nervous health - 0.2 x cortisol, and scales stress build-up by 1.35 - 0.5 x resilience;
digestiveEfficiency = 0.9 x (1 - 0.2 x senescence).

Aging: life stages are young (age below 60 game days), adult (below 6,000) and senior. Expected
lifespan = 9,000 x species (cat 1.05, dog 0.95) x (0.9 + 0.2 x longevity gene) x (0.85 + 0.3 x care
record) + extension; the care record closes 0.5% of its gap to the current wellbeing per game day (starting at 0.5).
calculateLifespan returns the game days left. Senescence runs from 0.0 at the start of the senior
years (6,000, or two thirds of a shorter lifespan) to 1.0 at the expected lifespan; it lowers
immunity by up to 30%, energy recovered in sleep by up to 30%, fitness gain by up to 40% and adds up
to 0.01 a day to fitness loss. A pet that reaches its expected lifespan dies of old age, except in
gentle mode (section 3.10.2). A life-extension potion (section 3.7.3) adds 1,500 game days and a
growth hormone pulse of 0.3. Breeding needs both pets to be adults (section 3.5.1).

Circadian rhythm: each pet has a CircadianRhythm that follows its sleep rather than causing it
(follow(deltaHours, timeOfDay, asleep)). Asleep, it cycles through light sleep (first 20 minutes of
each 90-minute cycle), deep sleep (to 60 minutes) and REM; awake, it is drowsy when sleep pressure
(0.7 x homeostatic drive + 0.3 x time of day) exceeds 0.6. Sleep debt grows by 8/24 of each waking
hour and falls by 16/24 of each sleeping hour (up to 24 hours); its level (debt / 12, at most 1.0)
doubles fatigue build-up at most and lowers cognitive capacity. The preferred sleep window is
11 pm - 5 am for cats and 10 pm - 6 am for dogs; at night the pet falls asleep at fatigue above
0.7 - 0.2 x night or energy below 0.3 + 0.05 x night, where night (0.0 - 1.0) is how close the
hour is to the middle of the window.

processDigestion(FoodItem{bulk, nutrition, hydration, digestion}) adds nutrition x absorption,
water and the digestive effect, pulses serotonin, then fills the stomach (eat). processExercise(
type, duration) builds fitness (per session: play 0.05, walk 0.06, exploring 0.05, running around
0.04) and pulses serotonin; the caller takes the energy it uses.

3.2.1 Time Management System

The server keeps one clock, chosen at startup (-time-scale game, 24x, 4x or realtime). Each
update advances the active pet, by the clock's game time converted to game days (saved pets
live on in the household's care, 3.10.1). While the
game is paused (section 3.10) the clock records the time but advances nothing, so no game time
passes and nothing is made up later.
3.2.2 Needs Management System
cppclass NeedsManager {

        float decayRate;        // How quickly need increases
        float criticalThreshold; // When need becomes urgent

        Priority priority;      // Impact on overall well-being
    };
    
    enum NeedType {
        HUNGER, THIRST, SLEEP, EXERCISE, SOCIAL,

Physical needs (hunger, thirst, sleep, cleanliness, medical care) are copied from the vital
stats. Psychological needs (exercise, social, mental stimulation, affection, exploration) decay
over time and are met by matching care: play (including hide and seek) meets exercise and mental
stimulation; petting meets affection and social; grooming and treats meet affection; training
meets mental stimulation and social; exploring meets exploration and exercise; walks (section
5.2) meet exercise. A low psychological need produces a pet request (section 3.9); each need at
its critical level lowers happiness by 0.02 per game day.
3.3 AI Behavior System
3.3.1 Behavior State Machine
cppclass BehaviorStateMachine {
    enum BehaviorState {
        IDLE, SLEEPING, EATING, PLAYING, EXPLORING,
        SOCIAL_INTERACTION, GROOMING, EXERCISING,
        SICK, DISTRESSED, HAPPY, EXCITED, HIBERNATING,
        INVESTIGATING       // Curious at home; EXPLORING is a trip
    };
    
    struct StateTransition {
        BehaviorState fromState;
        BehaviorState toState;
        function<bool()> condition;
        float probability;
    };
    
    void update(float deltaTime);
    void addTransition(StateTransition transition);
    BehaviorState getCurrentState();
    void forceState(BehaviorState newState);
};

Implementation: each pet has a state machine (built when needed, not saved) whose transitions all
start from any state and have probability 1.0, so behavior is deterministic and consistent. In
priority order: EXPLORING (on a trip), SICK (health below 0.3 or a serious illness), DISTRESSED
(wellbeing below 0.3), SLEEPING (tired, or asleep and not yet rested; easier at night, section
3.1.2), EXCITED and HAPPY (good mood and energy), EATING (hungry), then a discretionary behavior
(PLAYING, SOCIAL_INTERACTION, INVESTIGATING, GROOMING or EXERCISING) when its score passes 0.6,
else IDLE. GROOMING scores 0.6 x (1 - cleanliness) + 0.3 x conscientiousness + 0.3 for cats, and
restores cleanliness by 0.05 per game day (dogs 0.025) and lowers stress by 0.02; EXERCISING scores
0.5 x (1 - exercise need) + 0.5 x energy level when energy is at least 0.6, and gives 0.5 play
sessions of exercise and uses 0.08 energy per game day. A discretionary behavior's score combines
personality, the learned liking for the matching care (section 3.3.2) and the learned reward for
the behavior itself (reinforcement learning). Hibernation is applied before the state machine.
The machine records its transitions.

The state shown to the player as an activity line (for example "Biscuit is playing by itself") is
chosen this way. A hibernating pet, a trip ("is out exploring") and a game of hide and seek ("is
hiding somewhere") take precedence over the behavior state.
3.3.2 Learning System
cppclass LearningSystem {
    struct ExperienceRecord {
        UserAction action;
        EnvironmentState context;
        EmotionState petEmotion;
        float reward;           // Positive/negative reinforcement
        DateTime timestamp;
    };
    
    void recordExperience(ExperienceRecord experience);
    float predictReward(UserAction action, EnvironmentState context);
    void updateBehaviorWeights();
    PersonalityAdjustment getPersonalityShift();
};

struct InteractionPreference {          // One per interaction type
    float affinity;                     // Learned like (+) or dislike (-), -1.0 to 1.0
    int experience;                     // Interactions learned from
};

Each interaction updates the preference for its type from how the pet experienced it: its innate
reaction score / 0.3, limited to -1.0 to 1.0. The learned preference is left out so that
preferences follow the pet's nature and when care is given rather than reinforcing themselves; a
pet that dislikes attention learns to dislike petting however often it is petted. Each interaction
counts by its repeat weight (section 3.3.2, repeated care), so repeats in quick succession add less
experience and move the preference less. Early interactions are averaged equally;
once established, each new interaction moves the preference by at least 2%, so a loved pet's
behavior stays consistent unless the way it is treated changes over time. A preference has half
of its full influence on behavior after 10 interactions. Preferences do not decay; they are shown
to the player as likes (affinity >= 0.25) and dislikes (affinity <= -0.15).

Experience records: every kind of care the pet takes part in is recorded (recordExperience) with
the pet's mood (excited, happy, calm or upset), dominant emotion, reward (its emotional valence,
-1.0 to 1.0) and repeat weight; the last 200 are saved. A running estimate per care and mood
(averaging over about 20 weighted experiences) gives predictReward(action, mood) with a confidence of
n / (n + 5), falling back on the care's estimate across moods (confidence n / (n + 20)) when the mood
has fewer than 3. When a pet asks for attention it asks for play or petting, whichever it expects to
enjoy more: confidence x prediction + (1 - confidence) x learned preference. getPersonalityShift sums,
over the last 50 records, the traits each care develops (as in evolveTraits) times reward and weight,
plus neuroticism for disliked care; trends of 1.0 or more are shown as "Lately becoming".
updateBehaviorWeights turns the Q-values into each mood's best-rewarded behavior and relative
weights (positive values only), shown as "Has learned you respond to".

Reinforcement learning: each pet has a Q-learning system (saved with the pet). When the owner
gives care while the pet is in a discretionary behavior, the pet learns Q(context, behavior) with
the care's emotional valence as the reward (-1.0 to 1.0); the context is the pet's mood (excited,
happy, neutral or upset). Rewarded behaviors are chosen more often, discouraged ones less, through
the learned reward term in the discretionary score (clamped to -1.0 to 1.0, weight 0.3). The
learned values are used directly rather than through epsilon-greedy exploration, so behavior stays
consistent.

Personality development (evolveTraits): experiences move traits by intensity x 0.01. Enjoyed care
develops matching traits (play: playfulness, energy; petting: affection, loyalty; training:
conscientiousness, intelligence; exploring: curiosity, openness; walks: energy), and any enjoyed
care makes the pet slightly calmer and more loyal. Scolding raises neuroticism and lowers
agreeableness; injuries, illness, accidents and throwing up raise neuroticism; loneliness and
neglect raise independence and neuroticism and lower loyalty over time. The traits at the first
change are kept as a baseline, and the player is shown traits that have moved 0.05 or more from
it. Babies inherit genes, not their parents' acquired changes.

Repeated care: the same kind of care given in quick succession counts less towards personality
change and reinforcement learning. Each kind of care keeps a count of recent repeats that halves
every 3 real minutes; care is weighted 1 / (1 + count), so the nth repeat in a row counts 1/n. The
weight scales the trait changes and the learning reward but not the care's effect on vital stats.
Below a weight of 0.5 the result tells the player that more of it right away won't change how the
pet grows.

Memories: the long-term store holds up to 5,000 memories. Long-term memories fade at a rate
scaled by importance; at the default time scale a full-strength memory lasts about 17 hours
(trivial), 2 weeks (minor), 4 weeks (moderate), 8 weeks (significant) or 6 months (major) of real
time, and formative memories do not fade.

Validation: before care is applied, it is checked against the pet's state. A full pet is not
hungry, a clean pet does not need grooming, a very tired pet will not play, a stressed or tired
pet will not train, and a sleeping pet accepts only food, water and medical care. Refused care
changes nothing, earns no points and returns the reason (for example "Biscuit is not hungry.").
The description of each interaction is shown as the tip of its care button.

The player's care actions are Feed, Drink, Pet, Play, Groom, Heal (medical care) and Treat
(rewards); training and exploring are activities (section 3.8).
3.4.2 Care Variants
cppstruct CareChoice {      // The variant of the care being given
    Supply food;          // FEEDING, REWARDS
    Supply toy;           // PLAYING ("" to play together)
    PetRegion region;     // PETTING
    TrainingMethod method;// TRAINING
    EnvironmentChange change; // ENVIRONMENT_CHANGE
    MeetingOutcome meeting;   // SOCIAL_INTRODUCTION

Each variant adds to the innate reaction score (section 3.9) and applies its own effects and
lesson (the variant's lesson takes precedence over the general one):
Food: taste adds to the reaction; nutrition scales the meal (and stomach fill), hydration adds
water, digestion changes digestive health (negative: an upset stomach), and toxic food causes
poisoning (an illness, section 3.11.2, starting at severity 0.4 and affecting heart and nerves).
Basic food per species is free and unlimited; other foods come from the pantry (section 3.7.3).
Toys: species fit adds to the reaction; exercise and mental stimulation replace play's defaults;
some calm; most wear out after a number of uses. Catnip affects about two cats in three (fixed
per pet, from its identity, standing in for genetics).
Petting regions: per species, a base liking plus, for sensitive regions, (affectionate - 0.5) x 0.3
- (neuroticism - 0.3) x 0.4 times the region's sensitivity.
Training methods: progress x 1.4 (clicker, needs the Training Clicker and a treat), x 1.3 (treats,
uses one), x 1.0 (praise, liked more by pets that love attention) or x 0.4 (scolding: reaction
-0.6, stress +0.1, neuroticism up).
Environment changes (cat: box, window perch, food foraging, scratching post, toy swap; dog: sniffing
game, new smells, den, frozen food toy, toy swap): mental stimulation, exploration, exercise and
calming (scaled by 0.5 + neuroticism), with a liking from personality. Novelty = days since the
same change / 3, up to 1, scales the effects and liking.
3.4.3 Social Introductions
SOCIAL_INTRODUCTION introduces the active pet to another saved pet. Meeting quality = the mean of
both pets' sociability ((extraversion + agreeableness + (1 - territoriality) + (1 - neuroticism))
/ 4) + species (dog-dog +0.1, cat-cat -0.1, cat-dog -0.15) + history (an existing relationship
adds (bond - 0.3) x 0.5 - rivalry x 0.3; a first meeting -0.05), limited to 0.0 - 1.0. At 0.6 or
more they play together, at 0.45 or more they keep a cautious distance, below that they hiss or
growl. Both pets' relationships are updated with (quality - 0.45) x 2 (times the repeat weight);
a first meeting sets the starting bond and rivalry. Pets whose bond minus rivalry is at least 0.2
are friends, otherwise rivals, described from that score. The active pet receives the meeting as
care; the other pet's mood, stress and social need follow how it went. Both are saved. Lessons
explain how to introduce cats, dogs, or a cat and a dog.
3.5 Evolutionary System
3.5.1 Genetics and Reproduction
cppclass GeneticSystem {
    struct Genome {
        map<TraitType, GeneAllele> traits;
        vector<Mutation> mutations;
        float geneticDiversity;
    };
    
    struct Breeding {
        DigitalPet parent1;
        DigitalPet parent2;
        float compatibilityScore;
        DateTime breedingCooldown;
    };
    
    Genome crossover(Genome parent1, Genome parent2);
    void mutate(Genome& genome, float mutationRate);
    float calculateCompatibility(DigitalPet pet1, DigitalPet pet2);
    DigitalPet createOffspring(DigitalPet parent1, DigitalPet parent2);
};

Each pet has a genome whose personality genes match its personality traits (using the allele
values, so traits do not drift lower with each generation). The player breeds the active pet with
another saved pet. Both must be at least 7 game days old, have health of at least 0.6 and
happiness of at least 0.5 (adults: 60 to 6,000 game days old, section 3.1.2), be at least 0.3 compatible, and be neither hibernating, exploring nor
dead; breeding can still fail by chance, more often for less compatible pairs. The baby's genome
is a crossover of its parents' with mutation, its personality is inherited from both parents
(mutation rate 0.05) with the genetically based traits taken from its genome, and it is saved in
its own slot. Parents, mate and offspring relationships are recorded, the baby's generation is one
more than its parents', and each parent waits 3 game days before breeding again.
The season scales the chance of success by its breeding modifier (spring 1.3, summer 1.0, fall
0.8, winter 0.5, blended over the first 5 days of a season), averaged over the two pets'
environments; the chance is at most 1. Two pets can have at most 5 babies together; each parent
counts its babies per mate, and either count reaching 5 stops the pair.
Breeds (section 3.12): two parents of the same breed have a baby of that breed, with looks from its
genome and a pattern from a parent; any other pairing has a mixed breed (a domestic shorthair or
longhair cat by coat length, or a mixed breed dog) whose build, ears, muzzle, coat, legs, tail,
colors, pattern and eyes each come from one parent, whose size is between theirs, whose lifespan
factor is their average, and which has a tendency only if both parents have it, at the average of
their strengths halved. Its lineage records both parents and their breeds (and grandparents'
breeds for a mixed parent) and which parent each feature came from. Two merle parents have a
double merle (1 in 4), merle (2 in 4) or the breed's other pattern; a double merle has the eye
tendency and a 50% chance of deafness.
3.6 Social System
3.6.1 Multi-Pet Interactions
cppclass SocialSystem {
    struct Relationship {
        string petId;
        RelationshipType type;  // Friend, rival, mate, offspring, parent
        float bondStrength;     // 0.0 to 1.0
        vector<SharedExperience> history;
        DateTime lastInteraction;
    };
    
    void introduceAnotherPet(DigitalPet& newPet);
    void processGroupActivity(vector<DigitalPet*> participants);
    void updateRelationships(float deltaTime);
    float calculateGroupHappiness();
    void handleConflict(DigitalPet& pet1, DigitalPet& pet2);

Implementation (core/group.go, social.go): introduceAnotherPet is section 3.4.3.
processGroupActivity(activity, pets) has the active pet and one to three other saved pets play,
nap or (all dogs) walk together; each needs energy above the activity's cost + 0.1 and must be
awake, home and not hibernating. For each pair, harmony = meeting quality (section 3.4.3, with
history (bond - rivalry - 0.2) x 0.25 from each side, or -0.05 for strangers) + the activity
(play: 0.1 x (mean playfulness - 0.5); walk: +0.1; nap: +0.1 if both scores are at least 0.5,
otherwise -0.15) + cooperation 0.1 x (mean agreeableness - 0.5) - territorial crowding (each cat
loses 0.05 x (group size - 2) x territoriality), limited to 0.0 - 1.0. A pair below 0.45 clashes
(handleConflict): if their dominance differs by 0.15 or more, the lower pet backs down after a
growl or hiss (stress +0.05; bond change harmony - 0.45); otherwise they scuffle (both stress
+0.15, happiness -0.1, a hardship of 0.2; bond change 3 x (harmony - 0.45)) and the clash halves
the pair's harmony. Dominance = 0.35 x extraversion + 0.3 x territoriality + 0.2 x (1 -
neuroticism) + 0.15 x (1 - agreeableness), -0.2 for young pets; the group's pecking order and leader
are reported. Pairs that don't clash signal by species and harmony (friendly at 0.6 or more,
wary below), as text. Each pet's harmony is its mean over its pairs: the active pet takes the
activity as SOCIAL_INTRODUCTION care, the others as a meeting; good company (0.6 or more) releases
oxytocin and develops extraversion and agreeableness; the activity uses its energy, play and walks
exercise (one and 1.2 play sessions) and a nap relieves 0.15 x harmony fatigue. Every pair's
relationships record the shared experience (what they did, at each pet's age) and bond change
(harmony - 0.45) x 2. calculateGroupHappiness = mean happiness x (0.6 + 0.4 x harmony), where
harmony = 0.5 + (mean relationship score among pets that know each other - 0.2), limited to
0.0 - 1.0. updateRelationships(deltaTime): relationships fade only after 100 game days without
shared time (bond, affection and rivalry -0.002, trust -0.001 per game day), family bonds no lower
than 0.3. The server saves every pet in the group (POST /api/group).

Prices are set for about 250 points an hour of steady play; the everyday items take about 40

no less than half. Decorations suit a personality and together change anything by at most 6%,
except effects marked uncapped (the night lamp halves night-time stress for a nervous pet).

Upkeep: the water fountain's filter (300 game days), the bed's bedding (200), the flea collar (500)
and the first-aid kit's uses (3) run out; a lapsed item works at reduced strength. Replacements,

dental chews and cat grass are care supplies (3.7.3).

Seasonal items are sold, and work, only in their real season. Seasons follow the real calendar for
the hemisphere the player chooses (northern or southern), and the game's weather and breeding
season follow the same calendar.

Holidays: 20 holidays (New Year, Lunar New Year, Valentine's Day, Nowruz, Holi, Easter, Eid

with a decoration, a cosmetic and a treat or toy, sold from 7 days before to 7 days after. Movable
dates are computed (astronomical new and full moons, solar longitude, the Gregorian and Julian
Easter rules, the Hebrew calendar and the tabular Islamic calendar) rather than read from a table.
At most one holiday item may be bought per game session. A parent can turn any or all holidays off
(parent PIN; this computer only); a holiday that is off has no shop and its items are hidden.

Cosmetics: 50 everyday, plus seasonal and holiday ones, in six slots (head, eyes, neck, collar, tag,
body), one worn per slot. They change only appearance and are shown at playdates as IDs from the
game's list, which the hub checks (no free text).

3.7.3 Supplies
Supplies are consumables built on the interaction package's item system: Item templates with
rarities, an ItemCatalog per pet, an Inventory as the pet's pantry (quantities; toys with uses),
and a Shop that applies discounts and takes payment from the pet's Friendship Points. Each
species has its own foods, treats and toys (a few, such as milk, table scraps and the puzzle
feeder, are for both). Rarities unlock by lifetime points earned: uncommon 50, rare 150, epic 300,
legendary 600. The pantry holds 40 units. Two unlocked supplies are 25% off each calendar day, chosen from the date. A
purchase buys a pack (for example 3 meals or 10 treats). The life-extension potion (legendary, 1,000
points) is a health supply kept in the pantry and given with POST /api/potion (section 3.1.2).

3.7.4 Home Stars and the House
Home Stars belong to the player, not a pet: 3 per trip, 10 per new place, 10 to 50 per
achievement, 5 for a day's goals, 5 for a day with 10 minutes of play, and 20 and 60 more for 7 and
30 such days in a row. They buy house upgrades (2,400 in all) that apply to every pet (air
filtration, which needs a 20-star filter every 300 game days; climate control; laundry room;
playroom; sunroom; multi-pet feeding station; pet door to a fenced yard; catio; home vet corner;
quiet room) and house looks (wallpaper, floor, window view, nameplate). They are kept as a ledger in
household.json: each entry has an ID (random for repeatable earnings, a hash of what it was for
when it can happen once), so devices merge by taking every entry from both. The household is synced
through the hub as a sealed record, like a pet's save.

3.7.5 Families: Points and Inheritance
A baby starts with no points and no belongings. While a child is young (60 game days), a living
parent can give it Friendship Points; after it grows up, only once the parent has died. A dead
pet's equipment, decorations, cosmetics and unopened supplies, and any of its points, can be passed
on to one living child, once. Pop-ups tell the player how long a newborn stays young, and again when
the active pet has 5 minutes of real play left before it grows up (with its parents' points).

3.8 Activities
3.8.1 Tricks
cppclass TrickTraining {
    // Cats: sit, come, touch, paw, high five, spin, hoop, bell, fetch, sit pretty, wave, and the
    // special roll over and play dead. Dogs: sit, come, touch, paw, down, stay, high five, spin,
    // bow, hoop, fetch, weave, roll over, play dead. Difficulty 1 - 5; most need an easier trick
    // first (for example stay needs down, spin and hoop need touch, fetch needs come).
    
    float train(Trick trick);      // Returns progress; learned at 1.0
    string perform(Trick trick);   // Only learned tricks
};

Each session improves a trick by an amount that is larger for intelligent pets and pets that like
training and smaller for harder tricks. Training needs energy of at least 0.25 and is subject to
interaction validation (section 3.4.1).
Skill decay: training or performing a trick records the pet's age. 120 game days after that, the
skill falls by 0.25 per 120 game days. A trick the pet has learned (reached 1.0) never falls below
0.75 and is then rusty: it cannot be performed until training brings it back to 1.0, which is
reported as remembering it rather than learning it. Progress on a trick never learned falls to 0.
A trick can't be started until the trick it needs is learned. A cat can start rolling over or
playing dead only before 600 game days old and with playfulness above 0.6 and neuroticism at most
0.5; these special tricks don't count in shows or for the "every trick" achievement.
Shows (shows.go): a pet that is an adult, well, awake, not frail, with energy of at least 0.4 and
a game day since its last show enters against 5 made-up entrants (names from a fixed list, a
random breed of its species) whose scores are uniform in 40-85, 50-90 or 65-95 at Novice, Open and
Champion. Scores (0-100): Trick Show, for each of 3 different learned, non-special tricks, (20 + 4
x difficulty) x focus x 0.9-1.1, scaled by 100/120, +5 if the last is harder than the others;
Grooming, (40 cleanliness + 20 eyes + 20 teeth + 20 recent brushing) x (0.85 + 0.15 focus);
Agility (dogs), (40 fitness + 20 energy + 40 x average skill at weave, hoop, come) x focus; Playtime
(cats), (40 mental stimulation + 20 playfulness + 40 x average skill at fetch, touch) x focus;
Happiest, 50 happiness + 30 (1 - stress) + 20 care record; focus = 0.5 energy + 0.4 (1 - stress) +
0.1 (1 - sleep debt), from 0.3 to 1. Place = 1 + entrants scoring higher. Prizes for 1st-3rd:
60/30/15, 120/60/30, 200/100/50 points (at most 300 a calendar day) and 5/2/0, 10/5/2, 20/10/5
Home Stars, with a rosette; winning a level opens the next. Entry costs 20 (tricks, grooming) or
30 points; Happiest is free once a day. A show costs 0.15 energy and adds 0.05 x (1 +
neuroticism) stress. First places at Champion level in 3 different shows give the Grand Champion
title. No show judges looks against a breed standard.
3.8.2 Hide and Seek
The pet hides in one of six places and the player has two guesses. Finding it counts as play
and earns a 5-point game bonus at most once per reward cooldown. The player can stop the game at
any time; an unfinished game earns nothing.
3.8.2a Mini-games
Mini-games (minigames.go) are played on the page, which reports how well a game went as a number
from 0 to 1; nothing else is sent and nothing is scored or kept. Fetch (dogs) and the feather
wand (cats) count as playing, the puzzle feeder and the scent trail as environmental enrichment,
and gentle grooming as grooming, applied at intensity 0.4 + 0.6 x quality under the usual care
rules (refusals, the 3-minute points limit). A game opens once the pet has had its kind of care
(for enrichment, a trip or a change to its surroundings), and the list gives the refusal reason
before play. The pet's enjoyment is described from the quality: loved (0.8 or more), enjoyed
(0.5), had some fun (0.2), lost interest. The page computes quality as: fetch, good throws of 5
(the marker between 55% and 80%); feather wand, 0.3 x min(fast moves / 6, 1) + 0.3 x min(slow
moves / 6, 1) + 0.4 if the cat catches it (30 seconds, no limit in relaxed mode); puzzle feeder,
kibble found / kibble, with 3 + round(3 x intelligence) tiles, kibble under half (rounded up),
and 3 empty tiles allowed; scent trail, min(1, 6 / guesses) for 3 treats in 6 rooms; gentle
grooming, regions brushed with the fur (and gently where the pet's liking of the petting region
is below 0) / regions.

3.8.3 Exploring
cppclass Exploring {
    const float TRIP_LENGTH = 2.0;       // Game days
    const float MIN_LEVEL = 0.4;         // Energy, water and food needed to set out
    
    enum Outcome { TREASURE, NOTHING, INJURED };

Outcome chances: injury 12% (5 - 20%, lower for adaptable pets), treasure 55% (40 - 70%, higher
for curious pets), otherwise nothing of value. Unsafe weather adds 10 points to the injury
chance; night adds 5 and multiplies the treasure chance by 0.6. Treasures are souvenirs from the
place visited (souvenirs.go): each of the 12 places has 4 common souvenirs (weight 3 each) and a
rare one (weight 1 + 2 x curiosity). An injury costs
health 0.25, happiness 0.15 and energy 0.15, adds stress 0.2 and fear, and is remembered, making
the pet warier of exploring. An injured pet asks to be healed and cannot explore until it is.
A severe injury can kill the pet, or send it into hibernation in gentle mode. The pet cannot be
cared for while away. A pet that enjoys exploring investigates at home on its own (the
INVESTIGATING state); only the player starts a trip.
Places: a trip goes to one of the environment's locations: park, beach, meadow, farm, garden
(cats only), dog park (dogs only), forest, river, snowy hill, city, lakeside and mountain,
discovered after 0, 2, 3, 4, 5, 5, 6, 7, 8, 9, 10 and 12 finished trips (a trip called home early
does not count). The river can't be visited in winter, the snowy hill only in winter and the
lakeside only in summer. Environments saved before a place existed get it added. Cats go on a
harness walk with the owner. A long trip (longExploreDuration 5 game days) needs an adult that
isn't a senior with the "come" trick learned and at skill 1; it adds 3 points to the injury
chance, rolls the outcome a second time for a second souvenir, and costs 0.1 more energy. A friend
(a saved pet of the same species, alive, home, well, energy, water and food at least 0.4, to
which the pet's bond is at least 0.5, and fit for a long trip if it is long) is recorded with the
trip; when the trip ends the server loads it and ShareTrip gives it a copy of each souvenir, a
place visit, energy -0.1 (-0.2 on a long trip), happiness +0.05, exploration need +0.5, and both
pets bond +0.05 with a shared experience. A trip that wasn't an injury ends with a trip event with
chance 1/3 (tripevents.go): 30 events, 2 or 3 per place, handled like home happenings (3.8.4),
some of whose right choices add a souvenir from the place. A place adds (danger - 0.1) x 30 points to the injury chance and multiplies the treasure
chance by exploration value / 0.7 x (0.3 + 0.7 x resources), up to 90%. Each place's resources
(1.0 when untouched) fall by 0.3 when the pet finds a souvenir there and 0.1 when it finds nothing,
and grow back by 0.05 per game day.
Collection (collection.go): the household file keeps every souvenir any pet has found (a union
when devices merge; at startup the saved pets' souvenirs are added once). A place's set is complete
when its 4 common souvenirs are collected: 10 Home Stars, and 10 more for each rare souvenir; all
12 sets give the Curator achievement and 50 stars. The shelf holds up to 5 collected souvenirs (a
household setting; the newer wins on merge); while it holds all 5 of one place's souvenirs, every
pet's happiness falls at 0.98 times its rate, as a decoration. A gift moves a souvenir from the
active pet to a saved pet that has a relationship with it: bond +0.05, a shared memory, and
happiness +0.05. Gifts only pass between saved pets on this computer.

3.8.4 Home Happenings
Happenings (happenings.go) are 46 events at home, each with 2 or 3 choices, of which exactly one
is right: 18 for both species, 10 for cats, 10 for dogs and 8 for seasons and holidays (fireworks
around New Year, Lunar New Year and Diwali; a festive tree at Christmas; sweets at Easter,
Halloween and Valentine's Day; candles at Hanukkah, Diwali, Kwanzaa and Vesak, all only while
the holiday is turned on and within a week of it; hot pavement in summer and salt on paws in
winter for dogs; pollen in spring and moldy leaves in fall). Some need a condition: a smell or an
avoided litter box needs living area waste above 0.3, refusing food needs dental health below
0.6, a coat tangle a long, semi-long or shaggy coat, and hiding a warning sign.
The game server asks for one on each tick while time runs and the page was used in the last 2
minutes. A happening starts only when the pet is alive, home, awake, not hibernating, ill or
injured, none is waiting, 20 minutes of play have passed since the last, and a minute since the
last try; each try succeeds with chance 0.1. It is picked at random from those that fit and that
haven't come in the last 7 days. It waits 10 minutes of play for a choice; closing it, or letting
it pass, changes nothing. The choices are listed from a starting point set by a hash of its ID.
The right choice: happiness +0.05, stress -0.03, 5 Friendship Points (at most 25 a calendar
day), its own effect, and counts toward Happy Helper (25 right choices). Effects: calm (stress
-0.08, happiness +0.03), play (happiness +0.06, play needs met at 0.5), stimulation (mental
stimulation +0.3), cleaning (living area waste 0, stress -0.03), grooming (cleanliness +0.1).
Wrong choices: frightened (stress +0.12, happiness -0.05), frustrated (stress +0.06), upset
stomach (health -0.02, happiness -0.05, stress +0.05), hurt (health -0.05, stress +0.1), or
poisoning (chocolate, a toxic plant, holiday sweets, moldy leaves), the same illness as eating
chocolate, treated with Heal. Every choice shows what happened and the lesson.

3.9 Requests, Reactions and Preferences
cppstruct PetRequest {
    string action;      // Care that fulfils it: feed, drink, groom, pet, play, medic, train, explore, revive
    string message;     // Shown in a speech bubble
};

enum ReactionLevel { DELIGHTED, HAPPY, OKAY, RELUCTANT };

Requests are chosen most urgent first: revive (hibernating), heal (injured), water, food or
grooming when below 0.35, attention (play or petting, whichever the pet likes best) when it has
been alone for 3 game days or its affection or social need is low, then play, training or
exploring for low exercise, mental stimulation or exploration needs. The matching button is
highlighted.

Reactions: before care is applied, a reaction score is computed as 0.5 x the learned preference
(section 3.3.2) plus an innate score from personality, species and current state (for example,
hunger for feeding, energy and playfulness for play). The score selects a reaction level and text,
and scales the care's benefits by 0.6 to 1.4.

Attention: how much a pet enjoys being handled is, by nature, (affectionate - 0.5) x 0.6 -
(independence - 0.5) x 0.4 + (extraversion - 0.5) x 0.2 - (neuroticism - 0.5) x 0.2 - 0.05, plus
0.1 for dogs. At or above 0.1 the pet loves attention, at or above -0.15 it tolerates it, and
below that it prefers its own space (with random personalities, roughly 27% / 39% / 34% of cats and
41% / 38% / 20% of dogs). Petting's innate score adds (loneliness - 0.2) x 0.8 and subtracts 0.08 for
each recent petting (overstimulation, fading with the 3-minute half-life of repeated care);
grooming uses half the attention score and the same overstimulation. Petting, grooming, play,
training and walks given to a reluctant pet are unwanted attention: stress rises 0.1, happiness
falls 0.12, the emotional response is annoyance and fear instead of pleasure, and the lesson shown
explains the signs that a cat or dog has had enough.

3.9a Help and Sound
The page holds the 8-step tour and 8 first-time tips (shop, house, breeding, shows, collection,
family, games, explore). The household file records the IDs shown (TipsSeen, from a fixed list,
merged as a union; POST /api/tips/seen refuses any other), so each is shown once per household;
the status carries the list. Sound (sounds.js) is synthesized with the Web Audio API from 19
recipes of oscillators and filtered noise; nothing is downloaded. The player's sound settings (on,

setting, SoundOff in the household file (PIN-protected like the other parental settings, merged
with the other settings by time), silences every sound and hides the player's sound settings.

3.9b Themes, Projects and Keepsake Books
Themes (themes.go): ISO week number mod 12 picks dental, enrichment, grooming, hydration, training,
senior, calm, explorer, friendship, nutrition, safety or paws. Hydration and paws (8 weeks apart
in a round) swap when the hydration week is in winter or the paw care week in summer, by the real
season for the household's hemisphere. Each has a care guide topic (teeth, exercise, grooming,
water, training, senior, stress, outdoors, company, feeding, safety, paws; the five not in the
species guides are added to both), a preferred weekly goal kind (used when it is among the week's
options) and a list of happenings: the first that fits comes as the week's first happening, once
a week. Two happenings were added for themes: a stale water bowl, and a senior stiff on the
stairs (seniors only).
Projects (projects.go, GET /api/projects): Grand Champion (Champion wins of the active pet, 3, or
done if the household has the achievement), the collection (complete sets of 12), the house
(upgrades owned of all), generations (highest genome generation among saved pets, of 5), and the
care tier of one species with the largest share of its purebred breeds among saved pets.
Keepsakes (keepsakes.go): pages are added to the pet's save (at most 120) for: home (made, or
"born"), grew up, senior, first trick, first trip, each place discovered, each ribbon
(show/level/place), each set completed, first baby (its name), first best friend (bond 0.8, its
name), and each holiday played (once a year, checked once a day). Each page keeps the age, date,
look and outfit. The text comes from fixed templates. When the pet is saved, the server writes
<data dir>/books/<pet ID>.json with its name, species, breed, look, parents, pages, a memorial for
a pet that has died (age, cause, tricks learned, places visited, ribbons, its strongest like, the
pet it was closest to) and whether the memorial candle is lit (kept between writes). GET
/api/books lists books; ?id= returns one with page text, outfit cosmetics and its family
(parents, their parents, and children, from the other books). A book stays after its pet is
deleted, unless delete_book is set when deleting; POST /api/books/delete removes the book of a pet
no longer saved. Book IDs must match [A-Za-z0-9_-]{1,80}.

3.10 Session and Lifecycle Management
3.10.1 Pausing
Time passes only while the player is playing. Time stops when the player presses Pause, when the
player has not used the page for the away-pause period (2 minutes by default), and while the
program is not running. While time passes, the other living saved pets live on in the
household's care (householdtime.go): the server adds up the game days played and every 5 minutes
loads each saved pet that is alive, not hibernating, not away exploring and not paused by the
player (HouseholdPaused), adds the days to its age, raises its food, water, energy and
cleanliness to at least 0.8, happiness to at least 0.7, lowers stress and fatigue to at most 0.2,
empties its living area, keeps its needs at 0.8 or more, checks for death of old age, and saves
it. It earns no points and doesn't progress an illness. Every pair of pets that have met, both
alive and living on (the active pet always is), grows 0.002 closer a game day, up to 0.8, both
ways. A saved young pet with a living parent gets the growing-up warning, and a saved pet that
dies of old age is announced with a pop-up.
3.10.2 Hibernation (Gentle Mode)
cppclass Hibernation {
    const float CRITICAL_LEVEL = 0.1;
    const float REVIVE_LEVEL = 0.5;
    
    bool shouldHibernate();   // hibernationEnabled && (health <= 0.1 || hydration <= 0.1 ||
                              //   (nutrition <= 0.1 && energy <= 0.1))
    void revive();            // Restores health, hydration, nutrition and energy to >= 0.5
};

Hibernation is an option the player selects per pet, when creating it or later; it is off by
default, so a neglected pet dies (section 3.1.2). In gentle mode a pet reaching a critical level
hibernates instead: its stats, age and mood stay as they are and it does not respond to care
until the player revives it. Turning gentle mode off does not wake a hibernating pet.
3.10.3 Deleting Pets
Deleting a pet asks twice: first to confirm, then to type that pet's name exactly. Deletion
removes the pet's save and all of its backups.

3.11 Species, Living Area, Illness and Care Lessons
The game teaches real pet care. Each pet is a cat or a dog, chosen at creation (pets saved before
species existed are cats), and care, lessons and warning signs follow its species. Cats and dogs
cannot breed together; a baby takes its parents' species.
3.11.1 Living Area
cppclass LivingArea {

empties the bowel and bladder outside and counts as exercise.
3.11.2 Illness
cppstruct Illness {

    float severity;       // 0.1 at onset, +0.04 per game day, up to 1.0
};

A living area dirtier than 0.6 can cause illness (a cat: urinary tract infection; a dog:
intestinal parasites) at 0.3 x (waste - 0.6) / 0.4 per game day, and respiratory health below 0.4
can cause a respiratory infection, both scaled down by immune strength. An illness costs
0.04 x severity health per game day and harms its system (urinary: frequent urination and stress;
parasites: digestion; respiratory: lungs); at severity 0.3 the pet behaves sick and asks for care.
Eye health below 0.35 can cause an eye infection, and dental health below 0.3 dental disease, at
0.3 x the shortfall's share per game day (scaled by immune strength); treatment restores eye
health to 0.7 and is a dental cleaning that restores dental health to 0.9. Medical care also gives
fluids, bringing kidney health back up to its reserve.
It worsens until treated with medical care, which cures it; it can come back if the cause remains.
Untreated, it can kill the pet, or send it into hibernation in gentle mode.
3.11.3 Teaching
Lessons: each kind of care returns a short, species-specific explanation of why it matters
(InteractionResult.lesson); treating an illness explains how to prevent it.
Warning signs: the pet shows symptoms before problems become serious (a dirty living area, a dog
waiting by the door, sneezing, tiring quickly, signs of stress, an upset stomach, each illness's
signs, and recent events such as accidents), each with what it means and a care guide topic.
Care guide: short lessons per species (feeding, water, litter box or bathroom breaks, exercise,
grooming, vet care, breathing, stress); topics related to current warning signs are marked.
Old age: seniors past 0.3 senescence show "Slowing down with age", and pets within 600 game days of
their lifespan that can die of old age show "Very old and frail" with the days left and the potion;
both link to a care guide page on older cats or dogs. Growing up and becoming a senior are events
(section 5.1).
Daily checklist: a real owner's routine for the current calendar day (cat: two meals, water,
scoop the litter box, play, brush; dog: two meals, water, three walks, play), counted from the care
given. It follows the real day rather than game time, so it shows a real pet's routine.

3.12 Breeds
cppstruct Breed {
    string id, name;          // e.g. "maine_coon", "Maine Coon"
    Species species;
    int tier;                 // 1 easy (from the start), 2 more care, 3 demanding care
    Body body;                // build, ears, muzzle, coat, legs, tail, size range
    vector<Color> colors;     // coat colors the genes pick from
    vector<Pattern> patterns;
    vector<Color> eyes;
    map<Trait, float> temperament; // typical personality traits
    vector<Tendency> tendencies;
    float lifespan;           // relative to the species
};

21 cat breeds and 22 dog breeds. A new pet of a breed has personality traits drawn within 0.15 of
the breed's typical temperament (other traits random), a genome matching its personality, and
looks picked from the breed's by its size, color, pattern and eye genes. Its tendencies (each at
strength 1) and lifespan factor are the breed's; the body's lifespan is the species' factor x the
breed's. Breeds whose defining looks come from a condition that harms the animal (Scottish Fold,
Munchkin, Dachshund, Corgi) are not included.

Tendencies change existing simulation effects, applied after the limits on item effects so care
can offset but not remove them: high energy (exercise and stimulation needs x1.3), low energy
(exercise x0.75), grooming need (coat dirt x1.4), skin care (x1.3), short airways (weather stress
x1.5 above 27 C, airway damage x1.3, tiredness x1.15), feels the cold (weather stress x1.5 below
10 C), feels the heat (x1.3 above 27 C), joints (senior fitness loss x1.25, trip injury +2 points),
heart, food-motivated (hunger x1.15, food-reward training x1.2), separation stress (alone stress
x1.3), kidney disease, eyes and teeth (predispositions, section 3.1.2). Each has a care lesson.

Congenital deafness: a white cat is deaf with probability 0.2, 0.4 or 0.7 for zero, one or two
blue eyes, a white Boxer 0.18 and a double merle 0.5; half of these are deaf in one ear (hearing
0.5), half in both (0). Words, clicker and scolding train at 0.25 + 0.75 x hearing; hand signals
and reward (1.25, needs treats) don't depend on hearing.

Unlocking: tier 2 needs the All Grown Up and Daily Carer (all of a day's goals on 3 days)
achievements, and tier 3 also Nurse (an illness treated) and Attentive Carer (an adult with a
care record of at least 0.8, from 300 game days old), earned by any of the player's pets. The
household (section 4.2) records achievements, merged across devices; saved pets from before are
scanned once. Pets from before breeds become the species' default breed (Domestic Shorthair or
Mixed Breed) with looks from their genes, and their new body systems start healthy.

Drawing: pets are drawn as SVG from their look (pet-art.js): body parts from the breed's features,
the pattern clipped to the body, eye colors, a pose per state, and cosmetics placed on the head,
eyes, neck, collar, tag and body. At playdates only a breed ID from the game's list is sent; the
hub refuses unknown breeds or one of another species, and visiting pets are drawn in their
breed's typical look.

4. Data Management
4.1 Persistence Layer
cppclass DataManager {
    struct SaveData {
        DigitalPet petState;
        DateTime lastSaveTime;
        vector<HistoryEntry> careHistory;
        UserPreferences preferences;
        UnlockableContent unlocks;
    };
    
    void saveToLocal(SaveData data);
    void saveToCloud(SaveData data);
    SaveData loadFromLocal();
    SaveData loadFromCloud();
    void synchronize();
};

Save slots: each pet has its own save file, and the player can create, switch between and delete
pets. The active pet is saved automatically (every minute by default), when the player presses
Save, when switching or creating pets, and when the program exits. The previous five saves of
each pet are kept as backups. On startup the most recently saved pet is restored; a damaged save
is replaced by its newest working backup.
Saves read or written are kept in an in-memory cache (least recently used first out, up to 32 MB
of pet data) along with the file's modification time and size; a load or pet list entry uses the
cache only while the file is unchanged, so a damaged or replaced file is always read and checked.
Save contents: each save records, besides the pet, its care history (the last 500 entries: each kind
of care with how the pet took it, achievements earned and events from section 5.1), achievements
(unlock times kept with the pet; 12 milestones with rarities from common to legendary), unlocks
(places discovered, shop items owned, foods and toys in the pantry, tricks learned, species) and
statistics (play time, interactions, longest life, highest happiness, achievements), with the game
speed and autosave interval as preferences. Achievements are checked on each update and announced as
events.
Cloud (saveToCloud, loadFromCloud, synchronize): see section 4.2. Sync state is kept in cloud.json
per pet: the hub's version and a hash of the pet data when last synced. A pet has changed locally
when its pet data hash differs (so saving an unchanged pet is not a change) and on the hub when the
hub's version differs. Changed on one side only: that side's copy wins (upload, or download with the
local save kept as a backup). Changed on both: the copy last played (the pet's last update time)
wins. New on the hub: downloaded into a new slot. Deleted on the hub: reported and no longer synced;
the local copy is kept. If the active pet is downloaded, it is reloaded. Syncs run at startup
(before restoring the last pet), every 5 minutes, on request and on exit.
4.2 Cloud Integration
cppclass CloudService {
    void uploadPetData(string userId, DigitalPet pet);
    DigitalPet downloadPetData(string userId);
    void enableSocialFeatures(string userId);
    void shareAchievement(Achievement achievement);
};
(getNearbyPets(Location) was removed for safety: the game collects no location; see section 6.2.)

Implementation (internal/hub): the cloud service is a hub, which any Gochi server can run (-hub with
a join code, on its own HTTPS address, hub.addr, default :8443), or which runs on its own as gochihub
(section 6.3). Players never choose a name: registering with the join code returns an account key
(32 random bytes; the hub stores its SHA-256 hash) and a handle the hub picks from fixed lists, a
color, an animal and a number from 10 to 99 (such as "Blue Otter 42"); accounts are stored under a
random ID. Other devices sign in with the account key alone. HTTP API at /hub/v1: register; list,
get, put (with the base version: a stale upload is refused with 409 and the hub's version) and delete
pets, keyed by a hash of the pet ID; get the profile (handle and sharing) and set sharing; the
achievements feed; and AR playdates (section 5.2). Requests with fields the hub doesn't expect are
refused. uploadPetData / downloadPetData store and return a pet's whole save file, encrypted by the
game (section 6.2), with only its key, version, size and last-played time readable (at most 4 MB per
pet, 50 pets and 64 MB per account, 10,000 accounts); the hub keeps one previous version, and a
deleted pet leaves a marker so other devices don't upload it again. enableSocialFeatures sets whether
the player shares achievements (off for a new account). shareAchievement takes only an achievement's
ID (from the game's list) and the pet's species (a registered species); the hub fills in the
achievement's name, icon and description, and posts it with the player's handle to a feed of the last
200. Each player may make 120 requests a minute; requests without a valid account key (such as
registering) are limited to 120 a minute per IP address, so players sharing a network (as at a
playdate) don't share a limit. Accounts from hubs before handles are given an ID and a handle when
loaded, their username and area are dropped, and feed entries holding text players typed are
discarded.
4.3 REST API
cppclass RestAPI {   // /api/v1, enabled with -api-token; Bearer token required
    GET    /pets;  POST /pets;  GET /pets/{id};  PUT /pets/{id};  GET /pets/{id}/status;
    POST   /pets/{id}/interactions;  POST /pets/{id}/interactions/feed;  .../play;
};

The API works on copies of the saved pets and follows the game's rules: refused care returns
status 409 with the reason, and pets cannot be deleted through it (deletion needs the
confirmations in section 3.10.3). It has no accounts, social, sync or messaging routes.
Rate limiting: each client (by IP address) may make api_rate_limit requests (default 120) in any
minute, counted with a sliding window before authentication, so failed token guesses count. A
client over the limit gets status 429; responses carry X-RateLimit-Limit, X-RateLimit-Remaining
and, when limited, X-RateLimit-Reset. Clients with no requests in the window are forgotten.

5. Advanced Features
5.1 Environmental Simulation

Weather System: Affects pet mood, energy, and activity preferences
Seasonal Changes: Breeding cycles, food availability, behavior patterns
Location-Based Features: Different environments offer unique challenges and opportunities

Implementation: each pet has its own environment with weather, temperature, season and time of
day, which advance with that pet's game time (and so pause with it); weather changes are timed in
game hours. The environment multiplies the rates at which hunger, thirst and energy change,
nudges mood and stress, sets sleep quality (section 3.1.2) and changes exploring outcomes
(section 3.8.3). The page shows the surroundings under the pet's name.
Behavior: the pet's activity drive is the season's activity level (spring 1.1, summer and fall
1.0, winter 0.8) times a weather factor (hot 0.8, stormy 0.85, rainy, cold or snowy 0.9, clear and
comfortable (comfort above 0.7) 1.05, otherwise 1.0) times a time factor (1.1 for cats at dawn
and dusk, otherwise 0.9 at night). It scales the weights of playing and exercising among the pet's own
choices (section 3.3.1). Storms add 0.1 + 0.15 x neuroticism, and cold or snow 0.05 + 0.05 x
affection, to the weight of seeking company. Outdoor suitability is the weather's (its comfort,
0.2 in storms), halved at night; below 0.6 the pet doesn't ask to explore, a walk's reaction falls
by (0.6 - suitability) x 0.5, and a trip's injury chance rises by up to 12 percentage points in
proportion to the shortfall. At night the chance of finding a souvenir is multiplied by 0.6.
Places (section 3.8.3): a trip that ends without injury meets the social need by the place's social
bonus (park 0.6, city 0.5, beach 0.4, farm 0.3, forest 0.1, mountain 0.05) and the exploration need
by its exploration bonus. At a social bonus of 0.5 or more a pet with sociability 0.5 or more also
gains 0.05 happiness. Each trip adds the place's health risk (park and farm 0.05, beach and city
0.1, forest 0.15, mountain 0.2) times max(1.2 - immune response, 0.1) to the pet's parasite
exposure; at 1.0 the exposure resets and the pet gets parasites. Resources regrow at the base rate
times the season's food availability (spring 0.9, summer 1.2, fall 1.1, winter 0.6).
A new season blends in from the previous one over its first 5 days. Each pet has a favorite
season from its personality (the highest of curiosity for spring, energy for summer, adaptability
for fall, and the mean of affection and 1 - energy for winter); its mood modifier rises by 0.1 in
that season and falls by 0.08 in the opposite one. The season also scales breeding (section 3.5.1).
Events: each server tick compares a snapshot of the active pet before and after the update and
records what changed on its own (hunger, thirst, a new warning sign, illness or recovery, a trip
ending, a trick getting rusty, growing up or becoming a senior, hibernation, death) in an event system that keeps the last 100
events and passes them to registered handlers (the server logs illness, hibernation and death).
GET /api/events?after=n returns the active pet's events after event n; the page lists the latest
under "Recently". Care the player gives is reported in its response, not as an event.

5.2 Augmented Reality Integration

Real-World Interaction: Use device camera to place pet in real environments
Exercise Tracking: Encourage physical activity that benefits both user and pet
Social AR: Virtual pet playdates in shared physical spaces

Implementation: the server keeps the AR scene; an AR client (camera, plane detection, WebXR or
a phone app) reports what it sees through /api/ar endpoints: session control, detected surfaces,
camera pose and light estimates. The active pet is placed on a surface and its animation follows
its behavior. Gestures on the pet are care: tap = petting, double tap = play, long press =
feeding, swipe = throwing a ball (play), subject to the same validation as the care buttons.
Exercise tracking records the player's walk; every 500 m counts towards the pet's exercise need
as one play session (at most two per walk). The web page's AR view is such a client: with WebXR
it finds surfaces by hit testing from the center of the view; without it, it shows a drawn room.
Playdates: players on the same cloud hub (section 4.2) meet in one place, each with the active pet
from their own game. A player starts a playdate and gets a six-character code (from an alphabet
without look-alike characters); up to five others join with it. Each game sends a card of fixed
fields: the pet's hub key, species (registered), whether young, sociability (0 to 1), why it can't
play as a code (gone, hibernating, exploring or asleep) and which of its species' sprite states it
shows. The hub refuses any other value and builds the card every member sees: an ID derived from the
account and pet key (meaningless elsewhere) and the name "<handle>'s <species>". In AR each player
taps the agreed spot to mark the center; each member has a slot, and the client places its pet 1 m
from the center at an angle of 60 degrees per slot. About once a second the page posts its pet's
position relative to the center to its server, which forwards it (the hub keeps it within 5 m, on the
floor, in 10 cm steps, at most 0.5 m per change) and gets back the members and the events since the
last it saw. Tapping another
pet makes the player's pet meet it as in an introduction (section 3.6.1: both sociabilities, species
and the pet's earlier meetings decide the quality), recorded as care with points; the server reports
the play to the hub as the other player's handle, the quality and the bond. The hub writes the
event's text (core.MeetingText with the two cards' names), and the other pet's server records the
same meeting from its side ("played at a playdate") when it next updates. Members that send nothing
for 30 seconds are removed; a playdate ends when empty. Playdates are kept in the hub's memory only
(at most 500 at once, the last 50 events each). Hub routes: POST /hub/v1/playdates (start),
/playdates/{code}/join, /update, /play and /leave. Game routes: GET and POST /api/playdate (start,
join, leave), POST /api/playdate/update and POST /api/playdate/play.

5.3 Machine Learning Adaptation

User Pattern Recognition: Learn user's schedule and care preferences
Predictive Care: Suggest care activities before needs become critical
Personalized Content: Adaptive challenges and goals based on user engagement

Implementation: the server keeps an OwnerSchedule in <data dir>/owner.json: a weight for each of
the 168 hours of the week. Whenever the player is present (any use of the page), the current hour's
weight grows by 1/6, at most once every 10 minutes; all weights decay by a factor of 0.85 per week,
and an absence of an hour or more starts a new visit. With at least 6 such steps over 3 visits it
predicts: an hour is usual if its weight is at least 35% of the busiest hour's; the usual end of a
session is the end of the run of usual hours containing now; and the summary names the busiest
weekday and weekend parts of the day (such as "weekday evenings").
Predictive care: Forecast(horizon) copies the pet (through its save) and advances the copy in 60
steps, recording each request (section 3.9) it starts to make that the pet isn't making now, at
most 3, soonest first. The status's forecasts look ahead until the usual end of play (between 10
minutes and 2 hours of real time) or 30 minutes if that isn't known, converted to game time at the
current game speed, and give each forecast's real time. The page shows them as "Coming up".
Adaptive goals: each calendar day the pet gets three goals at a difficulty level from 1 to 5:
the routine care (section 3.10.4's checklist) given least over the last 7 days relative to how
often it is due, target its daily target + floor(steps/2); an activity (level 4 and above, learn a
new trick, if any are left to learn; otherwise from level 3, explore steps - 1 times; 2, practice tricks 2 + steps times; 1, play twice, or train
twice if play was the neglected care); and a happiness level of min(max(60 + 5 x round(level),
happiness + 10%), 95%), where steps = floor(level - 1). Each goal pays round(level) x 5 Friendship
Points when completed, and is announced as an event. At the start of each day, the level rises by
0.5 if at least two thirds of the last day's goals were completed and falls by 0.5 if none were
completed but some were tried. Goals are part of the pet's save.
After a pet's first day the activity goal is the best-scoring of: the first-day activity (1.0),
practice a rusty trick (1.5), renew upkeep due within 50 game days (1.3), brush teeth (0.6, +0.6
x teeth tendency, +0.6 if dental health is below 0.6), wipe eyes (0.8, +0.5 below 0.6 eye health;
eye tendency or eye health below 0.8), a home change not made for 5 game days (0.8), a trip to
the least-visited discovered place (0.8), meet another pet (0.6) and a group activity (0.5), less
1 for any kind asked for in the last 3 days. The wellbeing goal is happiness, or calm (stress
under 0.3 for 20 minutes of play) when stress is above 0.4, comfort (stress under 0.4 for 20
minutes) in heat above 27 C or cold below 10 C for pets with a matching tendency, or steady care
(food and water above 0.5 for 30 minutes) from level 3 on days after a happiness goal. Minutes are
of the play clock, in steps of at most 10 seconds. A weekly goal (ISO week) rotates through teeth
on 5 days, 7 trips, 2 tricks, all goals on 3 days and 20 play sessions; it pays 100 points and 15
Home Stars.


6. Technical Implementation Details
6.1 Performance Requirements

Real-time Simulation: 60 FPS UI with background biological processing
Memory Efficiency: Target <500MB RAM usage
Battery Optimization: Adaptive processing based on battery level
Cross-Platform: iOS, Android, Windows, macOS compatibility

Implementation: the simulation runs in the server, one tick a second; the page only displays state.
A test plays twelve hours at the default pace (720 game days, care every 30 seconds) and requires
the heap after garbage collection to stay under 500 MB and grow by less than 20 MB from the first
hour, the save to stay under 1.5 MB, and the mean tick to be under 20 ms; measured: about 1.4 MB of
heap, an 866 KB save and 12 microseconds a tick. A pet keeps at most 1,000 long-term memories (the
strongest; older saves are trimmed when loaded) and 500 history entries, so its save stops growing.
Battery: the page polls /api/status every 2 s, every 5 s on battery and every 15 s on low battery
(20% or less, from the Battery Status API where the browser has it), when it also stops animations;
a hidden page doesn't poll, and animations stop under prefers-reduced-motion.
Cross-platform: the game and the hub are pure Go (CGO off); make release builds both for Windows,
macOS and Linux on amd64 and arm64, each in a folder with web/ and configs/. iOS and Android play
in the browser against a computer running the game.

6.2 Security and Privacy

Data Encryption: All user data encrypted at rest and in transit
Privacy Controls: Granular permissions for social features
Child Safety: COPPA-compliant for users under 13
Offline Mode: Full functionality without internet connection

Implementation:
In transit: the hub always uses HTTPS (TLS 1.2 or later), with the configured certificate or else
a self-signed ECDSA P-256 certificate it makes on first start and keeps (hub-cert.pem, hub-key.pem),
printing its SHA-256 fingerprint. When the game connects, it probes the hub's certificate: one this
computer trusts is checked normally from then on; otherwise its fingerprint is pinned in cloud.json and
every later connection must present it. Hub addresses default to https://, and plain http:// is
refused except for a hub on this computer. The game serves HTTPS too when given a certificate and key
(server.tls_cert and server.tls_key, or -tls-cert and -tls-key; both checked at startup). Every
response carries X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN and Referrer-Policy:
same-origin.
At rest on the hub: the hub client seals each save before upload with AES-256-GCM under a key
HMAC-SHA256(account key, "gochi save encryption v1"), a random 12-byte nonce, and the pet's hub key
as additional data, stored as {"gochi_sealed": 1, "nonce", "data"}; downloads are opened the same way,
and unsealed saves from older versions are accepted. The hub keeps only the account key's hash, so
its files can't be decrypted on their own; nothing else about a pet is stored on the hub.
At rest locally: saves, backups, cloud.json, owner.json, parental.json and devices.json are written with mode 0600
in directories made 0700 (existing ones too). Saves aren't encrypted locally: the key would have to
be stored beside them; the operating system's disk encryption is the means for that.
Privacy controls: sharing achievements is off until chosen (section 4.2). Learning the play
schedule (section 5.3) can be turned off and erased (/api/privacy).
Child safety: an optional parent PIN (4 to 8 digits), stored as a 16-byte salt and 100,000 rounds of
SHA-256 in parental.json, is then needed to connect to or disconnect from a hub, see the account key,
change sharing, start or join a playdate, rename or delete a pet, unpair devices, and change privacy
settings; 5 wrong PINs refuse every PIN for 5 minutes, each later wait doubling (up to a day) until a
right PIN, with the count kept in parental.json across restarts. Connecting to or disconnecting from a
hub, changing sharing, the account key, the PIN and privacy settings are accepted only from this
computer, not from paired devices. COPPA compliance is a legal obligation of
whoever operates a hub for children; the software collects no personal information and gives parents
control of what is shared.
No personal information and no messaging: the game asks for nothing about the player, pet IDs are
random ("pet_" and 32 hex digits), and pet names (1 to 24 printable characters) never leave the
computer. Nothing a player types reaches another player: other players see only hub-chosen handles,
species, sprite states, achievements from the game's list, and text written by the hub; the hub
refuses unknown fields and values outside its lists. Playdate numbers are coarse so they can't carry
messages: sociability, play quality and bond are rounded to tenths, and positions are on the floor
(y is 0), in 10 cm steps within 5 m of the center, changing at most every 0.9 s by at most 0.5 m per
axis. Two modified games could still signal slowly through pet movement; nothing typed can pass. Nearby pets, areas, chosen usernames, free-text
achievements and playdate messages were removed, as were the unused account (email and password),
location, friend-request, sync and WebSocket parts of the REST API package, the unused social cloud
service and the old page scripts. What remains shared beyond fixed values is a pet's sociability, its
playdate position (as above) and the timing of actions.
The game's server: by default it listens on 127.0.0.1 only. Every request's Host must be "localhost"
or an IP address (stopping DNS rebinding). Requests that change something must be JSON (Content-Type
application/json) with no Origin or Sec-Fetch-Site from another site, and other sites' requests to
/api/ are refused outright; responses carry no CORS headers. When the server listens on the network,
requests from other devices need a device token: /api/pairing (from this computer only) makes an
8-character code valid for 10 minutes; POST /pair with the code sets an HttpOnly, SameSite=Strict
cookie, whose SHA-256 hash is kept in devices.json; each code pairs one device; 5 wrong codes from
one address make that address wait 5 minutes, without affecting other devices. The account key is given only to this computer (POST /api/cloud/key), never in the
cloud status. The REST API (/api/v1) keeps its bearer token and is subject only to the Host check.
Static folders aren't listed.
Robustness and limits: request bodies are limited to 64 KB (1 KB for /pair) and the servers have
read, write and idle timeouts; a hub reads at most 16 uploads at once, 2 per account. Loading a pet
refuses a save without its body or personality (the backup is used) and rebuilds or brings into range
everything else, and saving replaces any value that isn't a number with 0, so a damaged save can
neither stop the game nor make a pet unsaveable. Damaged stats.json, cloud.json and devices.json are
set aside at startup; parental.json is not, so damaging it can't remove the PIN. The REST API accepts
intensities from 0 to 1 only, places from the game's list, and no renames while a PIN is set. A player
can keep up to 100 pets. Reward waits and the start of a new day's goals use a play clock that runs
only while the game does (by the monotonic clock), so changing the computer's clock gains nothing; at
most two life-extension potions help a pet.
Offline: everything but the cloud features works without a network; at startup the game waits at
most 15 s for a hub before restoring the last pet.

6.3 Scalability Considerations

Modular Architecture: Plugin system for new features and pet types
Database Optimization: Efficient queries for large user bases
CDN Integration: Global content delivery for low latency
Microservices: Scalable backend services for different system components

Implementation:
Pet types: species are registered. A SpeciesDef holds everything that differs between species:
names and icon; lifespan factor, sleep window, twilight activity and self-grooming; toilet
style (litter box or outside), living area, mess request and warning sign, clean-up refusal, the
illness a dirty home causes, whether it goes for walks; care lessons, care guide, daily routine,
illness names and signs; liking for kinds of care, reaction texts, petting regions, home changes,
basic food, treats and its own supplies; and meeting odds with its own kind, introduction lessons,
threat and friendly signals, crowd sensitivity, leader text, group and conflict lessons.
RegisterSpecies checks a definition is complete; species_cat.go and species_dog.go register the two
species; elsewhere the game names them only as
the species constants and the default for saves without a species (cat). GET /api/species gives the page each species'
name, icon, clean-up label and whether it walks (pets are drawn from their breed, section 3.12).
Hub queries: the hub keeps each account's pets' information (key, version, size, last played) in
memory, loaded at startup and kept current by uploads and deletions, so listing pets, version checks
and the per-account space check read no saves.
Content delivery: static files are requested with ?v= and a hash of their contents and are then
served with Cache-Control: public, max-age=31536000, immutable, so a CDN or proxy can cache them;
other requests for them are revalidated.
Services: cmd/gochihub runs the hub alone over HTTPS (-addr, default :8443, -dir, -join-code,
-tls-cert, -tls-key), separate from any game; a game server can still run one with -hub, on its own
HTTPS listener.

8. Deployment and Maintenance
8.1 Release Strategy

Alpha Phase: Core biological simulation and basic care
Beta Phase: Social features and advanced AI
Launch Version: Full feature set with AR integration
Post-Launch: Regular content updates and seasonal events (seasonal and holiday items, 3.7.2,
already follow the real calendar and computed holiday dates, so they recur without an update)

8.2 Player Statistics (No Monitoring or Analytics)

The game does no monitoring or analytics. It collects no population-level statistics, tracks no
care patterns or session lengths, sends no crash reports and runs no A/B tests: nothing about how
the game is played leaves the player's computer.

Instead each player keeps their own statistics, which only they can see:
Pets Raised: How many pets they have raised, adopted and bred, how many are alive, died or were deleted, and how many times their pets hibernated
Deaths: Each cause of death and how many pets it took
Care: Every interaction, counted by kind (each pet also counts its own, in its save)
Each Pet: Its name, species, generation, age, whether it is alive or how it died, and how much care it had
Storage: stats.json in the player's data directory, readable only by their user account, kept apart from the pet saves so it lasts after a pet is deleted; never part of cloud sync, the hub or the REST API
